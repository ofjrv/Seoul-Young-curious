# 2차 미션: Markdown으로 AI 에이전트를 통제해 백엔드 완성하기

## 미션 한눈에 보기

이미 실행되는 영수증 처리 API에서 두 가지 문제를 찾아 고칩니다.

1. 잘못된 상호명과 금액도 등록되는 문제
2. 같은 요청이 두 번 들어오면 영수증도 두 번 생성되는 문제

코드를 많이 작성하는 것이 목표가 아닙니다. `TASK_SPEC.md`로 에이전트의 목표와 범위를 정하고, 결과를 테스트로 검증하고, 최종 코드를 자신의 말로 설명하는 것이 목표입니다.

## 준비물

- Node.js 18 이상
- Markdown과 코드를 편집할 수 있는 도구
- 이 폴더의 파일을 읽고 수정할 수 있는 AI 코딩 에이전트 1개

프로젝트용 npm 패키지는 별도로 설치하지 않습니다. AI 도구는 수업 전에 설치·로그인 또는 사용 가능 상태인지 확인하세요.

## 시작하기

1. 배포받은 ZIP의 압축을 풉니다.
2. 압축을 푼 폴더를 코드 편집기 또는 AI 코딩 에이전트에서 엽니다.
3. 해당 폴더에서 터미널을 열고 Node.js 버전을 확인합니다.

```bash
node -v
```

`v18` 이상이면 다음 명령을 실행합니다.

```bash
npm test
```

처음에는 4개 테스트 중 기본 실행과 등록·조회 테스트만 통과하는 것이 정상입니다.

## 수행 순서

1. `npm test`를 실행해 현재 상태를 직접 확인합니다.
2. `TASK_SPEC.md`를 자신의 문장으로 작성합니다.
3. 에이전트에게 다음과 같이 지시합니다.

   ```text
   AGENTS.md와 TASK_SPEC.md를 읽고 작업해줘.
   먼저 현재 코드와 테스트를 확인하고 구현 계획만 제시해.
   내가 승인하기 전에는 코드를 수정하지 마.
   ```

4. 계획을 검토하고 필요한 부분을 고친 뒤 구현을 승인합니다.
5. 에이전트가 수정한 파일과 차이를 직접 확인합니다.
6. `npm run check`로 전체 검증을 실행합니다.
7. `AI_WORKLOG.md`를 자신의 판단으로 작성합니다.
8. 2분 동안 요청 흐름, AI 제안을 바꾼 이유, 남은 한계를 설명할 준비를 합니다.

## 학생이 직접 결정하는 것

- 작업을 어떤 순서로 나눌지
- 에이전트에게 어느 정도 자율성을 줄지
- 시간·정확성·단순성 중 무엇을 우선할지
- AI의 제안을 채택·수정·거절할지
- 테스트 실패가 남았을 때 어떤 다음 행동을 제안할지

## 수정 가능한 코드

- `src/receipt-policy.js`
- `src/receipt-store.js`

테스트, 빌드 설정, 에이전트 규칙을 수정하면 보완 후 재제출 대상입니다.

## 완전 완료 기준

- `npm run check`가 성공한다.
- 보호 파일 검사와 4개 자동 테스트가 모두 통과한다.
- `TASK_SPEC.md`에 목표·범위·완료 조건·중단 조건이 있다.
- `AI_WORKLOG.md`에 AI 제안을 검증하고 수정하거나 거절한 근거가 있다.
- 자신의 코드 흐름을 2분 안에 설명할 수 있다.

## 부분 완료 제출

테스트가 모두 통과하지 않아도 제출할 수 있습니다. 실패 원인, 재현 명령, 확인한 증거와 다음 행동을 정확히 기록하면 과정 점수를 받을 수 있습니다. 이 경우에는 `npm run check`가 실패한 상태와 이유를 `AI_WORKLOG.md`에 그대로 기록하세요.

## 제출 전 확인

- 예상 소요 시간은 60~90분입니다.
- 수정 허용 파일은 `src/receipt-policy.js`, `src/receipt-store.js` 두 개입니다.
- 계획은 근거를 남기고 그대로 승인할 수 있습니다.
- 구현 과정에서는 AI 제안 하나 이상을 수정하거나 거절하고 그 이유를 기록합니다.
- 제출 파일명은 `[이름]_2차미션.zip`을 권장합니다.
